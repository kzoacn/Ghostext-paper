\section{Ghostext and a Guarded-Prefix Repair}
\label{sec:protocol-details}

\subsection{Packet and Replay Contract}

Ghostext separates authenticated packet recovery from token generation. Its
packet contains a 16-byte salt, a 12-byte header nonce, a 32-byte encrypted
header including its tag, a 12-byte body nonce, and an encrypted body with a
16-byte tag. The fixed bootstrap is therefore 60 bytes, and total overhead is
88 bytes. The internal header records protocol and algorithm identifiers,
body length, and a 64-bit configuration digest. The packet uses scrypt
($N=2^{14},r=8,p=1$), HKDF-SHA256 key separation, and ChaCha20-Poly1305.
These are standard components, not new cryptographic constructions.

The receiver first reconstructs and authenticates the bootstrap to obtain the
body length. It then reconstructs the body and authenticates it before releasing
plaintext. Both parties must agree on the model, tokenizer, prompt, candidate
policy, frequency table, and codec variant. The digest binds the configured
metadata values, but does not prove identity of every numerical-runtime setting
or every model-file byte. Exact weight and source hashes are recorded separately
in the experiment manifests. Low-entropy passphrases remain susceptible to
offline guessing; scrypt does not create entropy that the passphrase lacks.

\subsection{Candidate Source}

For each prefix, Ghostext masks specified special tokens, selects a descending
probability top-$p$ list capped at $K$, and removes candidates for which rendering
and retokenizing the entire generated prefix changes the token sequence. This
stepwise verification follows an established approach~\cite{yan2025tokenization}.
The remaining probabilities are renormalized and converted to positive integer
frequencies summing to $F$. Candidate ordering and tie-breaking are deterministic.
A singleton or an entropy below $h_{\min}$ causes greedy emission without
payload progress. An empty stable set causes failure or a fresh-packet retry.
The real-model configurations use $p=0.995$, $K=64$, $F=4096$, and $h_{\min}=0$.

Prefix verification establishes that the emitted text has the intended token
sequence at every accepted step. It does not preserve the unfiltered source:
removed probability mass is an explicit change. Moreover, a prefix can have
stable candidates now and none at a later step. We retain these failures and
retry trajectories in the artifact.

\subsection{Random Guard Bits and Prefix Recovery}

The repaired codec keeps the original integer-CDF update but changes its target
and stopping condition. For a $B$-bit segment $m$, draw an independent uniform
$g$-bit suffix $r$ and set $z=2^g\operatorname{Int}(m)+r$. Start with
$[L,H)=[0,2^{B+g})$. At each payload-bearing step select the subinterval
containing $z$, as in Eq.~\eqref{eq:integer-law}. Stop when
\begin{equation}
 \left\lfloor L/2^g\right\rfloor
 =\left\lfloor(H-1)/2^g\right\rfloor.
 \label{eq:guard-stop}
\end{equation}
The decoder outputs this common $B$-bit prefix. It neither knows nor reconstructs
$r$. With $g=0$, this is the legacy width-one codec. With $g>0$, recovery can
finish while many possible suffixes remain. Guard bits are random precision,
not extra authenticated application bytes that the receiver must deliver.

\begin{algorithm}[t]
\caption{Guarded segment encoding and mirrored decoding}
\label{alg:guard}
\begin{algorithmic}[1]
\REQUIRE segment length $B$, guard precision $g$, shared candidate source
\STATE Sender only: $r\gets U(\{0,\ldots,2^g-1\})$; $z\gets2^g m+r$
\STATE Both: $L\gets0$; $H\gets2^{B+g}$
\WHILE{$\lfloor L/2^g\rfloor\ne\lfloor(H-1)/2^g\rfloor$}
  \STATE Recreate the next quantized CDF from the shared prefix
  \STATE Sender selects the token whose integer subinterval contains $z$
  \STATE Receiver observes that token and rejects an empty subinterval
  \STATE Both replace $[L,H)$ with the selected subinterval
\ENDWHILE
\STATE Receiver returns $\lfloor L/2^g\rfloor$ as exactly $B$ bits
\end{algorithmic}
\end{algorithm}

The full implementation also enforces token budgets and deterministic no-payload
steps. Empty segments resolve immediately. The codec identifier and $g$ enter
the configuration digest; incompatible endpoints must not silently mix variants.

\begin{theorem}[Guarded coding bound]
\label{thm:guard}
For a uniform $B$-bit segment and independent uniform $g$-bit guard, consider at
most $T$ steps and at most $N$ candidates per step. Compare the guarded codec
with a $Q$ sampler using the same integer state transitions, prefix stopping
rule, horizon, and absorbing invalid states. Their transcript TV is at most
\begin{equation}
 \min\{1,TN/2^{g+1}\}.
 \label{eq:guard-bound}
\end{equation}
\end{theorem}

\paragraph{Proof.}
At any depth, the active intervals are disjoint subsets of the initial integer
domain. Every unresolved interval crosses a strict interior boundary between
two $B$-bit payload blocks, hence there are at most $2^B-1$ active intervals.
An interval of width $W$ has probability $W/2^{B+g}$ under the uniform target.
Multiplying this by the local bound $N/(2W)$ from
Eq.~\eqref{eq:local-rounding} and summing over active intervals bounds the
expected one-step TV by $N/2^{g+1}$. Sequential TV composition over $T$ steps
proves the result. Both laws include invalid and horizon-exhaustion outcomes;
none are conditioned away.

For two independent fixed-length uniform segments, their horizon contributions
add. The implementation's $g=128$, $N\le64$, and combined 6144-token budget give
a coding-only bound of approximately $2^{-110.4}$. This is not ``128-bit
steganographic security.'' Frequency quantization, source pseudorandomness,
filtering, retry conditioning, and the choice of stopping reference remain
outside this bound. In particular, Theorem~\ref{thm:guard} does not repair the
separate comparison in Theorem~\ref{thm:stopping}.
